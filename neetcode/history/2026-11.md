### Q1 [big-o] Doubling loop
**Asked:** Time complexity of `for (int i = 1; i < n; i *= 2) { count++; }`? (options: O(n), O(log n), O(n log n), not sure)
**Your answer:** "This feels like it would be O(n/2) as it seems to run linearly, but you only run half of the iterations of n as it doubles the count each iteration."
**Result:** Incorrect
**Correct answer / why:** O(log n). `i` doubles, so the distance left to n halves each step (n=16: i = 1,2,4,8 gives 4 iterations = log2(16)). O(n/2) would describe `i += 2`, and is O(n) anyway since constants drop.
**Follow-up:** Pushed back that nothing visibly halves; walked through the trace table. Rule refined: constant *factor* per step = log, constant *amount* per step = linear. Retry scheduled with `i /= 3` (see Q5).

### Q2 [java-lang] Integer caching
**Asked:** `Integer a = 1000, b = 1000; System.out.println(a == b);` prints?
**Your answer:** false
**Result:** Correct
**Correct answer / why:** false. `==` compares references for boxed types, and the Integer cache only covers -128..127. Use `.equals()`.

### Q3 [recursion] Naive fib complexity
**Asked:** Time complexity of naive `fib(n) = fib(n-1) + fib(n-2)`?
**Your answer:** Not sure
**Result:** Not sure
**Correct answer / why:** O(2^n). Each call branches into two, tree depth n. Memoization reduces it to O(n).
**Follow-up:** Weak spot. Draw the `fib(4)` call tree by hand in Phase 0 section E.
